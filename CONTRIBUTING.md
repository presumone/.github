# Contributing to PreSumOne

Contributions include documentation, bug reports, code, reviews, and learning resources. Read the target repository's README, requirements, and contribution instructions first. Its specific workflow takes priority. Follow our [Code of Conduct](CODE_OF_CONDUCT.md).

## Contribution workflow

1. For substantial work, discuss the problem and proposed scope with maintainers through an issue or the project's established channel.
2. Use a fork or assigned branch according to repository permissions.
3. Keep changes focused, write meaningful commits, and update affected documentation.
4. Run relevant checks and verify the affected behavior. Record checks you could not run.
5. Open a pull request describing the problem, changes, verification, and related issue. Include screenshots for visual changes where useful.
6. Respond to review feedback and let an authorized maintainer approve and merge.

Do not push directly to shared default branches unless maintainers explicitly authorize that workflow. Keep credentials, personal information, and private project material out of public contributions.

## Learner submissions

Official learning repositories contain specifications and starter materials. Use the fork, assignment repository, or branch required by the project instructions.

Include:

- Project title and ID, repository link, and working demo where required.
- Setup instructions and completed requirements.
- Evidence of working features and relevant validation or error handling.
- Known limitations and explanations of important decisions.
- Credits for external resources, collaborators, and tools used.

Submit work you understand and can explain. Disclose meaningful assistance, including AI assistance, and follow project-specific restrictions. Never present another person's work as your own.

## Collaboration and reports

Give respectful, specific feedback about the work. Explain why a change matters. Communicate blockers and changed delivery expectations early, and credit contributions fairly.

Bug reports should include reproduction steps, expected and actual behavior, and relevant environment details. Follow [SECURITY.md](SECURITY.md) for sensitive vulnerabilities.
