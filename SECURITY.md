# Security reporting

This repository contains PreSumOne community documentation. For vulnerabilities in another project, follow that repository's security policy first. Supported versions and fixes are determined by each project.

## Report privately

Do not post vulnerabilities, credentials, personal data, or exploit details in public issues, discussions, or pull requests.

If the affected repository offers GitHub private vulnerability reporting, use **Security → Report a vulnerability**. Otherwise, contact a project maintainer or organization owner through an established private channel and ask for a secure reporting destination before sharing details.

A dedicated security email has not yet been published here. Private vulnerability reporting must be enabled separately for each repository; this document does not enable it.

## Useful report details

- Affected repository, version or commit, and component.
- Description of the issue and potential impact.
- Minimal reproduction steps using test data where possible.
- Suggested mitigation or fix, if available.

Share only necessary information. Do not access other people's data or disrupt live services while investigating.

## Exposed credentials and follow-up

If you control an exposed credential, revoke or rotate it promptly. Notify the responsible maintainer privately with its location without copying the secret. Removing a secret from the current file does not invalidate it or remove it from history.

Maintainers can coordinate investigation, remediation, and disclosure with the reporter. No fixed response or resolution window is currently published.
